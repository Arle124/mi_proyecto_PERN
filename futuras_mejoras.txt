================================================================================
NOVAPALMA - PLAN DE FUTURAS MEJORAS Y SUGERENCIAS DE ARQUITECTURA
================================================================================
Fecha de generación: 2026-08-29
Proyecto: Sistema de Gestión Logística y Financiera Novapalma (PERN Stack)

--------------------------------------------------------------------------------
1. ARQUITECTURA Y CONSISTENCIA DEL BACKEND
--------------------------------------------------------------------------------

* Unificar la Capa de Controladores y Servicios en 'Dashboard' y 'Finanzas':
  - Situación actual: En 'dashboard.routes.js' y 'finance.routes.js', las 
    consultas a la base de datos (prisma.trip.aggregate, reduce, findMany) están
    escritas directamente dentro de las funciones de ruta de Express, rompiendo
    el patrón Controller -> Service que sí tienen usuarios, vehículos, 
    conductores y viajes.
  - Sugerencia: Extraer la lógica a 'dashboard.controller.js' / 
    'dashboard.service.js' y 'finance.controller.js' / 'finance.service.js'. 
    Esto homogeneiza la arquitectura en capas y permite testear las fórmulas 
    financieras de forma unitaria.

--------------------------------------------------------------------------------
2. RENDIMIENTO Y ESCALABILIDAD DE DATOS
--------------------------------------------------------------------------------

* Paginación y Filtrado Server-Side en '/api/viajes':
  - Situación actual: En 'trip.service.js', getAllTrips() ejecuta un 
    prisma.trip.findMany() sin límites de registros.
  - Impacto: A medida que la operación registre cientos o miles de viajes, 
    la consulta transferirá megabytes de datos innecesarios y saturará la 
    memoria del navegador.
  - Sugerencia: Implementar paginación mediante 'page' y 'limit' (o 
    cursor-based pagination) junto con filtros en el backend (por rango de 
    fechas, conductor, vehículo, producto).

* Automatizar el Soft Delete con Prisma Client Extensions:
  - Situación actual: En cada consulta se debe recordar agregar manualmente 
    '{ deletedAt: null }'. Si se olvida en un nuevo endpoint, se filtrarán 
    registros eliminados.
  - Sugerencia: Usar un Prisma Client Extension ($extends) en 'db.js' para 
    filtrar automáticamente registros con 'deletedAt != null' en lecturas y 
    convertir los 'delete' en 'update({ deletedAt: new Date(), activo: false })'.

--------------------------------------------------------------------------------
3. SEGURIDAD Y GESTIÓN DE SESIONES
--------------------------------------------------------------------------------

* Optimizar el ciclo de vida del JWT y el chequeo en Base de Datos:
  - Situación actual: En 'auth.middleware.js', en CADA petición HTTP entrante se
    hace una consulta SQL a la tabla 'refresh_tokens'. Esto anula la naturaleza
    stateless del JWT, convirtiéndolo en una consulta a PostgreSQL por endpoint.
  - Sugerencias:
    1. Enfoque Tokens Duales: Usar un Access Token (JWT de corta duración, ej. 
       15 minutos, verificado puramente con firma criptográfica sin tocar la BD) 
       + un Refresh Token rotativo (guardado en BD o cookie HttpOnly que solo 
       consulta la BD cuando el Access Token expira).
    2. Enfoque Cache/Redis: Si se requiere revocación instantánea en cada request,
       almacenar tokens activos o lista negra en memoria con Redis.

* Desacoplar Orígenes de CORS a Variables de Entorno:
  - Situación actual: En 'app.js', la URL 'https://mi-proyecto-pern.vercel.app' 
    está hardcodeada en el código fuente.
  - Sugerencia: Leer los orígenes permitidos desde una variable de entorno 
    'ALLOWED_ORIGINS' separada por comas.

--------------------------------------------------------------------------------
4. FRONTEND (REACT / VITE) Y EXPERIENCIA DE USUARIO (UX)
--------------------------------------------------------------------------------

* Descomponer Componentes Monolíticos (ej. 'Trips.jsx'):
  - Situación actual: 'Trips.jsx' tiene ~964 líneas (48 KB) y gestiona 
    simultáneamente modales de creación/edición, modales de confirmación, tablas, 
    filtros, formateo de divisas y estado.
  - Sugerencia: Modularizar en subcomponentes dedicados:
    - client/src/components/trips/TripTable.jsx
    - client/src/components/trips/TripFormModal.jsx
    - client/src/components/trips/TripDetailModal.jsx
    - client/src/components/trips/TripFilters.jsx
    - client/src/hooks/useTrips.js (Custom Hook de lógica y datos)

* Incorporar TanStack Query (React Query) o SWR:
  - Beneficios:
    - Elimina la sincronización manual de múltiples useEffect y banderas de carga.
    - Caché automático entre cambios de páginas/vistas.
    - Revalidación en segundo plano y mutaciones optimistas.

* Optimizar el Dockerfile del Frontend para Producción:
  - Situación actual: 'client/Dockerfile' ejecuta 'npm run dev -- --host' 
    (servidor de desarrollo de Vite).
  - Sugerencia: Usar un Dockerfile multi-stage con Nginx para servir los 
    archivos estáticos de 'npm run build', reduciendo memoria RAM y tamaño de 
    la imagen Docker.

--------------------------------------------------------------------------------
5. OBSERVABILIDAD, LOGGING Y MONITOREO
--------------------------------------------------------------------------------

* Logger Estructurado (Pino / Winston):
  - Reemplazar console.log y console.error por un logger estructurado en formato 
    JSON con niveles (info, warn, error) y correlation IDs (requestId) para 
    rastrear peticiones de extremo a extremo.

* Endpoint de Health Check ('/api/health'):
  - Agregar una ruta '/api/health' que valide la conectividad con PostgreSQL para 
    facilitar el monitoreo en plataformas como Docker, Render, AWS o Kubernetes.

--------------------------------------------------------------------------------
6. TESTING Y CALIDAD DE SOFTWARE
--------------------------------------------------------------------------------

* Suite de Pruebas Unitarias y de Integración con Vitest / Supertest:
  - Integrar pruebas unitarias de servicios y esquemas Zod con Vitest/Jest 
    ejecutables con 'npm test'.
  - Usar Supertest para pruebas de integración de endpoints sin requerir 
    navegador.

* Pipeline CI/CD (GitHub Actions):
  - Crear '.github/workflows/ci.yml' para ejecutar linter, validación de esquemas 
    Prisma, pruebas automatizadas y compilación de imágenes Docker en cada PR.

--------------------------------------------------------------------------------
7. PLAN DE PRIORIZACIÓN RECOMENDADO
--------------------------------------------------------------------------------

1. Corto Plazo (Quick Wins):
   - Extraer dashboard y finanzas a controladores/servicios dedicados.
   - Modularizar Trips.jsx en componentes pequeños y reutilizables.
   - Parametrizar orígenes CORS en el archivo .env.

2. Mediano Plazo:
   - Implementar paginación y filtros server-side en viajes.
   - Integrar React Query / SWR en el cliente frontend.
   - Configurar build multi-stage con Nginx en el Dockerfile del cliente.

3. Largo Plazo:
   - Migrar a estrategia Access Token (stateless) + Refresh Token rotativo.
   - Configurar pipeline automatizado de CI/CD en GitHub Actions.
